# Windows / Android UI 与功能对齐设计

## 目标

在保留 Windows 顶部导航、Android 底部导航差异的前提下，让两端页面内容、功能入口、操作语义和数据行为一致。重点恢复 Windows 待办页的“添加待办”按钮，并消除因窗口宽度导致的裁切或隐藏。

## 设计范围

### 1. 共享页面内容

- 待办：日期选择、回到今天、视图筛选、进行中/已完成统计、添加、编辑、完成、删除、流转到下一天使用同一套业务逻辑和按钮语义。
- 剪贴板、便签、笔记、番茄钟、标准时间和设置：复用相同的标题、图标、操作顺序和状态提示；只有触控手势、窗口尺寸和导航位置保留平台差异。
- 同步、删除、保存后的提示统一使用现有同步提示样式，并在两端立即刷新对应页面。

### 2. 待办工具栏布局

抽取共享的待办工具栏结构，按以下优先级布局：

1. 日期条占用剩余空间并允许收缩；
2. 回到今天、视图筛选、统计和添加按钮保持不可压缩；
3. Windows 在最小窗口宽度下仍显示添加按钮，必要时仅压缩日期文字和间距；
4. Android 使用紧凑高度和触控安全尺寸，但保留同样的操作顺序和入口。

所有工具栏按钮使用明确的最小宽度和 `Flexible/Expanded` 边界，禁止依赖可能溢出的固定总宽度。

### 3. 分割线主题

将分割线颜色统一放入主题语义色，不再使用黑色硬编码：

- 浅色模式使用清新的中等浅绿色，保证在浅紫背景上可见；
- 深色模式使用低透明度的深绿色，避免过亮；
- 统一边框粗细、透明度和圆角卡片边界；
- Windows 与 Android 的 TabBar、列表、侧栏、工具栏和卡片全部使用该语义色。

## 数据与错误处理

不修改同步协议和本地数据模型。所有新增、编辑、完成、流转和删除仍经现有 notifier/service 写入；写入完成后由现有状态流触发刷新。按钮在异步操作期间禁用，失败时保留原数据并显示现有错误提示。

## 验证

- Widget 测试覆盖 Windows 最小宽度下添加按钮仍可见且与日期条同一行。
- Widget 测试覆盖 Android 紧凑布局仍存在添加、视图筛选、统计入口。
- 测试两端共享待办操作的回调和刷新行为。
- 扫描主题和页面代码，确认目标 UI 分割线不再硬编码为黑色。
- 运行 `flutter analyze`、相关 Flutter 测试，并分别构建 Windows Release 与 Android Release。
