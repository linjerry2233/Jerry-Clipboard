# 云端数据清理功能问题与修复说明

## 结论

原“清理云端数据”并非只有一个故障，而是 Windows、Android REST、Android SSH 三条链路各有缺陷，同时清理后的自动同步还可能把本地数据重新上传。因此用户会看到“点击后没有效果”或“刚清空又恢复”。

本次将功能拆成两个独立操作：

1. **清理云端文件**：删除当前分支中的同步数据文件，保留 Git 提交历史。
2. **彻底清空云端及历史**：创建一个不带 parent 的空根提交，强制更新目标分支，使旧提交和旧数据不再能从该分支访问。

两种操作均不删除本地数据库，并在成功后暂停自动同步，避免本地数据在下一轮全量同步时被重新上传。

## 根本原因

### Android REST

- 删除请求没有携带配置中的 `branch`。当同步分支不是仓库默认分支时，程序会从目标分支读取文件 SHA，却尝试在默认分支删除，服务端会拒绝请求。
- 批量清理忽略了单文件删除失败，最后仍返回“成功”，甚至显示删除了 0 个文件。
- 删除结束后没有重新读取远端目录进行复验。

### Android SSH

- `git-receive-pack` 的成功状态格式是 `ok refs/heads/<branch>`，旧代码却判断该行是否以 `ok` 结尾，导致实际成功的推送被判定为失败。
- 按数据类型清理在 SSH 后端没有实现。
- 清理结束后没有再次 fetch 并检查远端 tree。

### Windows Git

- 只删除数据目录第一层的 JSON 文件，嵌套目录中的历史数据会残留。
- `reset` 等关键 Git 命令未检查退出码。
- 提交后没有检查远端跟踪分支中是否仍有数据文件。
- 暂存使用范围不够明确，现统一使用 `git add -A`，确保删除记录被提交。
- 当 Gitee 仓库已经超过容量配额时，服务端会拒绝“删除文件后再 push”和“空根提交强推”；此时普通清理按钮无法绕过平台限制。

### 公共行为

- 清理操作不影响本地数据库，但定时全量同步会再次把本地数据推到云端，造成“清理无效”的表象。
- 原界面没有区分“删除当前数据”和“删除分支历史”，容易让用户误以为普通删除会清除历史提交中的数据。

## 修复内容

- REST 删除请求显式传递目标分支。
- 任意单文件删除失败时立即返回错误，不再伪报成功。
- Windows 和 Android 在清理后都执行远端复验；只有复验通过才返回成功。
- Windows 改为递归删除同步数据文件，并检查关键 Git 命令结果。
- 修正 Android SSH receive-pack 成功状态解析。
- Android SSH 已支持按板块清理，并保留其他板块的 tree。
- 成功清理后关闭 `autoSyncEnabled`，界面同时停止当前调度器。
- 增加独立的“彻底清空云端及历史”按钮，并要求输入“彻底清空”二次确认。
- 历史清理会创建空 tree、无 parent 的根提交，再强制更新配置的远端分支。
- Android Token/REST 模式不执行历史重写，界面会明确要求切换至 SSH；普通文件清理仍完整支持。
- Windows 清理失败时显示脱敏后的真实 Git stderr，不再统一显示“冲突或网络错误”。

## 超过托管平台配额时

如果服务端已经拒绝所有 push，普通清理和历史重写都无法生效。恢复方式是使用托管平台账号权限删除并重建仓库，或联系平台管理员临时解锁后改写历史并执行 GC。

普通“清理云端文件”按钮不会隐式删除整个 Gitee 仓库：SSH Git 凭据只提供 Git 传输权限，不等同于账号级仓库删除 API 权限。仓库删除必须单独确认，并通过已登录的 Gitee 页面或明确配置的 API 凭据执行。

## 历史提交是否能彻底删除

从 Git 分支视角可以：重写后目标分支只剩一个空根提交，旧提交不再可达，普通 clone、pull 和分支历史中无法访问旧数据。

但应用无法保证托管服务商立即物理擦除旧对象。GitHub、Gitee 或自建 Git 服务可能在以下位置暂时保留不可达对象：

- 服务端 reflog 或垃圾回收等待期；
- 缓存、镜像、备份和审计日志；
- 其他分支、标签、Fork 或已经 clone 到其他设备的副本。

若数据涉及密钥或敏感信息，建议同时：

1. 删除指向旧提交的其他分支和标签；
2. 检查 Fork、镜像和 CI 缓存；
3. 轮换已经暴露的密钥或凭据；
4. 按托管平台流程联系管理员执行服务端清理。

## 验证

- `flutter analyze`：通过，无静态检查问题。
- Git 协议回归测试：覆盖标准 `ok refs/heads/...` 成功回包和 `ng` 失败回包。
- 空根提交测试：确认提交不包含 parent，并指向空 tree。
- 现有云同步安全与刷新测试：通过。
- Android 安装包需在连接设备上安装后，仅验证界面、配置暂停和非破坏性流程；不会在验收阶段擅自清理真实远端仓库。
