# NTP 标准时间与上海时区设计

## 目标

在 Windows 和 Android 共用一套低资源 NTP 时间服务：固定使用上海时区（`Asia/Shanghai`，UTC+08:00），支持预设及自定义 NTP 服务器，默认每 30 分钟同步一次，并在独立时间 Tab 显示精确到秒的数字时间。

## 已确认约束

- NTP 传输使用 UDP/123，不引入第三方 NTP 依赖。
- 自定义地址接受主机名或 IP，可选 `:端口`；省略端口时使用 123。
- 时区不可由设备时区覆盖，所有显示和计算统一转换为上海时间。
- 同步失败不得清空上次有效时间；界面显示失败状态并保留上次成功时间。
- Android 后台定时遵守 WorkManager 的最短周期限制，前台使用轻量定时器。

## 架构

### 配置与持久化

扩展现有 `AppSettings`，保持 Isar 单记录配置模型：

- 当前 NTP 服务器地址；
- 已保存自定义服务器 JSON 列表；
- 同步频率（分钟，默认 30，限制在安全范围）；
- 上次成功同步时间；
- 当前时钟偏移毫秒数。

旧数据库记录通过默认值兼容，不需要破坏性迁移。

### NTP 服务

新增独立 `NtpTimeService`：

1. 解析服务器地址，默认端口 123，拒绝空地址、非法端口和广播地址。
2. 构造标准 48 字节 NTP v4 客户端报文，通过 `RawDatagramSocket` 发送。
3. 使用发送/接收时间计算本地时钟偏移，设置单服务器超时，按服务器候选顺序故障切换。
4. 成功后保存偏移和同步时间；显示时间使用 `UTC + 8 小时` 的固定转换，不读取设备时区。
5. 失败时返回结构化错误，不覆盖最后一次有效偏移。

预设服务器初始列表：阿里云、腾讯云、国家授时中心、教育网和 `cn.pool.ntp.org`。列表保存在服务常量中，用户可选择其中一个作为当前服务器，也可切换到已保存的自定义地址。

### UI

- 主 Shell 新增“标准时间”Tab，显示 `HH:mm:ss` 大号数字、上海日期、当前服务器、上次成功同步时间和手动同步按钮。
- 设置页新增 NTP 卡片：预设服务器下拉框、自定义服务器输入/添加/删除、同步频率选择和立即同步按钮。
- 同步成功/失败沿用现有底部提示布局，位置位于 Android 底部导航栏上方。
- 时间页面只刷新数字时间，不触发数据库全量查询。

## 数据流

应用启动时加载 `AppSettings`，创建 NTP 服务并按保存配置启动前台定时器。时间 Tab 订阅服务状态；手动同步和定时同步共用同一串行入口，避免并发 UDP 请求。设置保存后立即更新服务配置并重新安排定时器。

## 错误与兜底

- DNS、连接、超时、报文长度、模式/版本、时间戳非法均归类为可展示错误。
- 候选服务器全部失败时，继续使用最近一次有效偏移；从未成功同步时显示本地时间并明确标记“未同步”。
- 频率输入被限制在 5–1440 分钟，默认 30 分钟；Android 后台由系统周期能力兜底。
- 同步请求设置 2 秒超时并保证 socket 释放，避免网络异常导致资源泄漏。
