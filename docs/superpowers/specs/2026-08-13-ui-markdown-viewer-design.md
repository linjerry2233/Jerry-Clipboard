# 主题化密集布局与 Markdown 查看/编辑设计

## 目标

统一 Windows 与 Android 的分割线主题、压缩待办/便签/笔记的顶部布局，并让便签与笔记默认进入只读查看模式；仅在用户明确点击编辑后进入键盘编辑。同时复用现有同步浮层展示 NTP 同步状态。

## 已确认的产品约束

1. 所有分割线使用主题紫色语义色，不使用黑色线条；阴影可以保留，但不得伪装成分割线。
2. Windows 待办宽屏顶部保持一行：日期选择、今天、视图/日期选择、完成统计、添加待办；添加待办固定在最右侧，完成统计位于其左侧。窗口变窄或 Android 继续使用现有响应式布局。
3. 已有便签/笔记点击进入查看模式，不自动聚焦、不弹出键盘；新建内容直接进入编辑模式。查看模式提供“编辑”入口，保存后回到查看模式。
4. Markdown 源文本继续作为唯一持久化格式，查看模式和预览模式使用 `flutter_markdown_plus` 渲染；编辑模式提供常用 Markdown 快捷工具，不引入重量级 AGPL 编辑器依赖。
5. Android 便签卡片高度约为当前三分之二；便签、笔记顶部搜索/工具区向上压缩，并与待办顶部高度保持一致。
6. NTP 手动同步成功或失败必须通过 `IncrementalSyncService` 的 `SyncToastEvent` 进入现有 `_SyncToastOverlay`，不再单独显示 SnackBar。

## 交互与状态

### 查看/编辑状态

- `selected == null`：显示列表/网格。
- 选择已有项：`editing = false`，渲染标题、Markdown 正文、元信息与“编辑”按钮。
- 新建项或点击“编辑”：`editing = true`，显示工具栏和文本输入；输入框仅在此状态可获取焦点。
- 显式保存后持久化并切回查看状态；自动保存仍可在编辑期间执行，但不改变页面状态。
- Android 返回键从详情回到列表，编辑中的未保存内容沿用现有保存策略。

### Markdown 能力

查看/预览至少支持标题、粗体、斜体、删除线、链接、引用、无序/有序列表、任务列表、代码块、分隔线和图片。工具栏只插入 Markdown 语法，不改变数据库模型，因此 Windows/Android 与云端格式兼容。

## 视觉规范

- 分割线优先使用 `Theme.of(context).dividerColor` 或 `colorScheme.outlineVariant`。
- 待办宽屏控件统一使用紧凑高度、较小内边距；完成统计为单行文本。
- Windows 便签卡片固定约 142px 高、顶部色条 4px、正文最多 3 行；“添加便签”卡片同高。
- Android 便签卡片约 128px 高、网格间距 8px、内部留白和字号同步缩小。
- 搜索框、列表与编辑器顶部留白统一收敛到 6–10px，避免顶部空间抢占内容。
- 状态提示只使用现有同步浮层，位置保持在底部操作栏上方。

## 技术边界

- 新增共享 `MarkdownDocumentViewer`，集中配置主题化 `MarkdownStyleSheet` 与图片渲染。
- 在 `StickyNotesPage` 与 `NotesPage` 内增加显式 `editing` 状态和只读详情组件。
- `TodoPage` 仅调整宽屏工具行，不修改待办数据/同步逻辑。
- `IncrementalSyncService` 暴露一个受控的 toast 发布方法，NTP 页面调用它。
- 不改变同步协议、Isar schema 或 Markdown 字段含义。

## 验收标准

1. 静态检查不再发现用于分割线的黑色颜色。
2. Windows 宽屏待办控件在一行内显示，添加待办最右、统计紧邻其左侧。
3. Android 点击既有便签/笔记不会弹键盘；点击编辑后才可输入，保存后可查看 Markdown 渲染结果。
4. 粗体、列表、代码、链接等工具插入的 Markdown 在两端查看一致。
5. Android 便签卡片高度明显降低，顶部区域与待办紧凑度一致。
6. NTP 手动同步提示与云同步提示的样式、位置一致。
7. Flutter 测试、分析、Windows 安装包构建及签名 Android APK 验证通过。
