# 剪切板按类型清空设计

## 背景

剪切板主页已有“全部、文本、链接、图片”类型筛选器，但“清空”按钮始终删除全部未固定记录，没有使用当前筛选类型。需要让清空操作只影响用户选中的类型，同时保护固定内容，并沿用现有增量同步机制。

## 目标

- 清空按钮按当前类型筛选删除未固定剪切板记录。
- 固定剪切板记录始终保留。
- 删除操作通过现有 `DataChangeEvent` 和墓碑同步机制传播到云端及其他设备。
- 清空完成后保留当前筛选、搜索和固定筛选状态并刷新列表。
- 无可删除内容时不产生数据库写入，并给出明确提示。

## 非目标

- 本次不直接修改云端仓库，不绕过现有同步服务。
- 本次不改变单条删除、复制、置顶和搜索行为。
- 本次不提供删除固定内容的入口；固定内容保护是强制规则。

## 数据层设计

在 `DatabaseService` 增强批量删除接口，接受可选的 `ClipboardItemType`：

- `null` 匹配所有未固定记录。
- `text`、`link`、`image` 只匹配相应类型的未固定记录。

删除查询必须在 Isar 侧完成过滤，避免将全部记录（尤其是图片数据）加载到 Dart 堆。批量删除在一个写事务中完成，并在事务前收集每条记录的 `syncId`。事务成功后，为每个记录发出已有的剪切板删除事件；没有 `syncId` 的本地记录不产生远端删除事件。固定记录不会被查询、删除或发事件。

Provider 增加带类型参数的清空方法，调用数据库接口后重新加载当前页面数据。

## 页面交互

主页沿用现有类型筛选器。点击“清空”后，确认弹窗根据当前类型显示清空范围，并明确说明“仅删除未固定内容，固定内容会保留”。

确认期间按钮显示加载状态，防止重复点击。完成后保留搜索词、类型筛选和固定筛选状态，刷新列表并显示实际删除数量；数量为零时提示没有可清空的未固定内容。数据库异常时保留原列表，显示失败原因，不显示成功消息。

## 同步边界

清空按钮只修改本地数据库。删除事件由现有增量同步服务处理，继续使用墓碑/删除清单同步到云端和其他设备。这样可以保持本地数据库、同步状态和远端提交之间的既有一致性策略。

## 验证计划

需要覆盖以下回归场景：

1. 全部类型只删除未固定文本、链接和图片，固定记录保留。
2. 文本、链接、图片筛选分别只删除对应类型。
3. 仅存在固定记录时删除数量为零且不产生事件。
4. 带 `syncId` 的记录逐条产生剪切板删除事件，无 `syncId` 的记录不产生远端事件。
5. 删除后筛选、搜索和固定筛选状态不变，列表立即刷新。
6. 数据库异常时不显示成功提示，原数据状态可重试。
