# NTP Shanghai Time Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a low-resource UDP NTP service shared by Windows and Android, fixed to Asia/Shanghai, with persisted server/frequency settings, preset/custom server selection, and a live standard-time tab.

**Architecture:** Keep configuration in the existing Isar `AppSettings` record. Put packet/address parsing and Shanghai conversion in small pure helpers, put UDP/socket lifecycle and failover in `NtpTimeService`, expose serialized state through `NtpTimeNotifier`, and render settings/time UI from that provider. The notifier owns one foreground timer and never performs database queries on each displayed second.

**Tech Stack:** Flutter/Dart 3.11, Riverpod StateNotifier, Isar, `RawDatagramSocket`, Material UI, existing `SyncToastOverlay`/settings navigation.

## Global Constraints

- NTP transport is UDP/123 with no third-party NTP dependency.
- Custom addresses accept hostname or IP with optional `:port`; omitted port is 123.
- All displayed/calculated time uses fixed Asia/Shanghai UTC+08:00, independent of device timezone.
- Sync failures retain the last valid offset and last successful time.
- Default sync interval is 30 minutes and accepted values are 5–1440 minutes.
- Android background scheduling must respect WorkManager minimum periodic interval.
- Every production behavior change starts with a failing Flutter test.

**Interfaces:**
- `NtpPacketCodec.buildRequest(DateTime sentAt) -> Uint8List` creates a 48-byte client request.
- `NtpPacketCodec.parseServerTime(Uint8List response) -> DateTime` validates mode/version/length and reads the transmit timestamp.
- `NtpSyncResult` contains `server`, `offset`, `roundTrip`, and optional `error`.
